# QA checklist

## Must pass

- It's 16:9 horizontal.
- Background is clean white.
- Xiaohei is present.
- Xiaohei carries the core action, not just decoration.
- No replicated old composition — a fresh metaphor for this article.
- The frame is quirky, creative, interesting.
- Clean and sparse; the subject is under ~60% of the canvas.
- One image, one core structure.
- Few, short, readable English labels.
- Orange only for the main path or arrows.
- Red only for key points, problems, reminders, or results.
- Blue only for secondary notes, feedback, or system state.

## Failure signals

Regenerate or locally edit when you see:

- A top-left title like "Common Pitfalls / Workflow / System Architecture / Roadmap".
- Xiaohei looking like a mascot, emoji, or cute cartoon.
- It looks like a PPT, course slide, or formal flowchart.
- Too many elements, arrows, or nodes.
- Text turned into long paragraphs.
- Background with paper texture, shadow, gradient, beige, or noise.
- A realistic UI screenshot or techy interface.
- Bad spelling or unreadable labels.
- Too stiff, with no absurd metaphor.
- Too similar to a bundled example in `examples/images/`.

## How to iterate

- **Too plain** — make Xiaohei the subject of the action; add one strange-but-coherent metaphor.
- **Too busy** — delete nodes; keep one action and 3–5 short labels.
- **Too cute** — emphasize deadpan, blank serious expression, not cute, not mascot.
- **Too PPT** — drop the title, borders, tidy grid, and excess arrows; switch to a hand-drawn scene.
- **Too much like an old case** — keep the core meaning, swap the main object and Xiaohei's action.
- **Bad text** — prefer a local edit; if spelling is badly off, regenerate with fewer labels.

## Delivery test

A strong image should first read as "a little weird", then become legible within one second.

If the first impression is a tutorial page rather than a quirky product sketch on blank paper, it fails.
