# PRD & Implementation Lifecycle Management

## Quick Start
Before starting work on any feature or closing out tickets:
1. Ensure the parent PRD issue exists on GitHub.
2. Ensure child implementation issues exist and are triaged properly.
3. Keep a local `task.md` to track implementation tasks.

---

## Workflows

### 1. Planning & Setup
- [ ] Create/retrieve the parent `prd(...)` issue.
- [ ] Decompose into smaller vertical slices (child implementation issues).
- [ ] Prepend all comments/descriptions with: `> *This was generated by AI during triage.*`
- [ ] Create an `implementation_plan.md` and a `task.md` checklist in the app data directory.

### 2. Verification Before Closing Child Issues
Before closing any child implementation ticket:
- [ ] Run typescript checks: `cd dashboard && npx tsc --noEmit`
- [ ] Run unit tests: `npm run test`
- [ ] Run the critique scanner: `npx impeccable --json --fast src`

### 3. Closing Child Issues
- [ ] Use `gh issue close <number> --comment "> *This was generated by AI during triage.* [Context of what was resolved]"`

### 4. PRD Walkthrough and Closure
Once all child issues are closed:
- [ ] Compile a comprehensive walkthrough report.
- [ ] Save the responsive HTML walkthrough in `docs/walkthrough.html`.
- [ ] Stage/commit the `docs/walkthrough.html` file to Git.
- [ ] Paste the markdown version of the walkthrough directly as the comment body of the closed parent PRD issue.
- [ ] Close the parent PRD issue.
