# PRD & Implementation Lifecycle Management

`<skill-dir>` below is the directory containing this `SKILL.md`. Run every
script from the root of the user's repository, not from `<skill-dir>`.
The scripts need `git`, `node` and an authenticated `gh`.

## Quick Start
Before starting work on any feature or closing out tickets:
1. Ensure the parent PRD issue exists on GitHub.
2. Ensure child implementation issues exist and are triaged properly. Each
   child's body names its parent as `Parent: #<prd>`, or the child is linked
   as a GitHub sub-issue; the verification script finds children either way.
3. Keep a `task.md` checklist of implementation tasks wherever this agent
   keeps working plans. Do not commit it unless the team wants it in the repo.

---

## Workflows

### 1. Planning & Setup
- [ ] Create or retrieve the parent `prd(...)` issue.
- [ ] Decompose it into small vertical slices, one child implementation issue each.
- [ ] Prepend every AI-written comment and description with: `> *This was generated by AI during triage.*`
- [ ] Write an `implementation_plan.md` and the `task.md` checklist.

### 2. Verification Before Closing Child Issues
Before closing any child implementation issue, run the project's own checks.
Find them in `package.json` scripts, the README or CI config; for example:
- [ ] Typecheck (e.g. `npm run typecheck` or `npx tsc --noEmit`).
- [ ] Tests (e.g. `npm test`).
- [ ] Any linter or scanner the project already uses.

If a check fails, fix it or report it; do not close the issue.

### 3. Closing Child Issues
- [ ] `gh issue close <number> --comment "> *This was generated by AI during triage.* <what was resolved>"`

### 4. PRD Walkthrough and Closure
Once all child issues are closed:
- [ ] Write a walkthrough report in `walkthrough.md`: what shipped, the child issues, key files, and how it was verified.
- [ ] Generate the responsive HTML version:
  ```bash
  node <skill-dir>/scripts/generate-walkthrough.js walkthrough.md docs/walkthrough.html
  ```
- [ ] Run the closing verification. It checks that child issues are closed, the
  walkthrough HTML exists, nothing else is uncommitted, and the typecheck and
  tests pass:
  ```bash
  bash <skill-dir>/scripts/verify-prd-closing.sh <prd_number>
  ```
  It detects `npm run typecheck`, `npx tsc --noEmit` and `npm test`. For
  anything else, pass the commands, and `--dir` when the app lives in a
  subdirectory:
  ```bash
  bash <skill-dir>/scripts/verify-prd-closing.sh <prd_number> --dir web --typecheck "pnpm typecheck" --test "pnpm test"
  ```
  Use `--typecheck none` or `--test none` only for a project that has no such
  check, and say so in the walkthrough.
- [ ] Commit `docs/walkthrough.html`.
- [ ] Post the walkthrough as a comment on the parent PRD:
  ```bash
  node <skill-dir>/scripts/post-walkthrough.js <prd_number> walkthrough.md
  ```
  This leaves the PRD open. Close it only once the user confirms, either with
  `gh issue close <prd_number>` or by passing `--close` on the post command
  above.
